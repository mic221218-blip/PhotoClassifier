# PhotoClassifier V2 方案 —— 规则分类

[English](v2-plan.md) | [简体中文](v2-plan.zh-CN.md)

> 状态：**已实现**（2026-10-18，决策 D1–D5 全部落实）——M1 规则引擎、
> M2 CLI、M3 GUI 接入、M4 文档均已完成，测试 160 个全绿。

## 1. 目标与范围

V2 把 V1.5 已入库的 EXIF 数据变成**自动分类标签**——不依赖 AI、完全离线、
完全可解释。每条规则都是一个作用于 `PhotoInfo` 的普通判断函数；每次命中都
生成人能看懂的原因。

**V2 范围：**

- 内置规则目录（夜景 / 高感 / 慢门 / 长焦 / 广角 / 大光圈），阈值可配置；
- 规则匹配引擎：EXIF 缺失绝不报错；
- 「为什么命中」说明，例如 `ISO 6400 ≥ 3200`；
- CLI：`classify` 统计报告 + `filter` 筛选命令；
- GUI：接通现有的筛选面板（复选框 + AND/OR + 实时数量），结果卡片显示
  自动标签 chips，详情面板显示命中原因。

**不在 V2 范围（后续版本）：**

- 图像内容识别（V3.5）、图像质量分析（V2.5）、用户自定义标签（V3）、
  导出/Lightroom（V5）、地图视图（V6 之后）。

## 2. 规则目录（V2 内置）

| ID | 名称 | 条件 | 默认阈值 | 缺失数据行为 |
| --- | --- | --- | --- | --- |
| `night` | 夜景 | 拍摄时间落在夜间时段内 | 18:00–06:00（可配置） | 无拍摄时间 → 不命中 |
| `high_iso` | 高感 | ISO ≥ 阈值 | 3200 | ISO 为空 → 不命中 |
| `slow_shutter` | 慢门 | 快门秒数 < 阈值 | 1/30 s | 快门为空 → 不命中 |
| `telephoto` | 长焦 | 焦距 ≥ 阈值 | 70 mm | 焦距为空 → 不命中 |
| `wide_angle` | 广角 | 焦距 ≤ 阈值 | 24 mm | 焦距为空 → 不命中 |
| `fast_lens` | 大光圈 | 光圈 ≤ 阈值 | f/2.8 | 光圈为空 → 不命中 |

EXIF 缺失永远不算错误：规则只是不命中，照片仍保留在「全部照片」视图中——
与 V1.5 的容错分级保持一致。

**分组维度**（不是规则，而是 CLI / GUI 的分组与筛选）：

- 按日期（`taken_at` → `YYYY-MM-DD`）、按相机（`camera`）、按镜头
  （`lens_model`）、按地点（有 GPS 坐标的照片）。

## 3. 架构设计

```
src/rules.py
├── RuleConfig        # 阈值（夜间时段、ISO、快门、焦距、光圈）
├── Rule              # id、名称、说明、判断函数、原因格式化
├── RuleMatch         # rule_id、名称、原因文本、命中值
└── RuleEngine        # 内置规则表 + evaluate(info) -> list[RuleMatch]
                      # classify(infos) -> {path: matches}
```

- **内置规则不建新表**：在 GUI/CLI 已加载的 `PhotoInfo` 列表上即时计算。
  理由：数据永远最新、无迁移风险、1 万张 × 6 条规则约 <100ms（需测试验证）。
- **阈值可配置**：集中在 `RuleConfig`（默认值见上表），日后设置界面或配置
  文件可覆盖，不必改代码。
- **用户自定义规则**：推迟到 V2.x（决策 **D2**）。需要 `rules` 表
  （id、名称、类型、参数 JSON），本方案先不建。
- **GUI 接入**：筛选面板的「标签」复选框换为规则复选框
  （夜景 / 高感 / 慢门 / 长焦 / 广角 / 大光圈）；AND/OR 生效；
  匹配数量实时更新；详情面板增加「规则命中」小节列出原因；结果卡片显示
  自动标签 chips。

## 4. 数据流

```
photos 表（V1.5）
        │  find_photos_under()
        ▼
PhotoInfo 列表 ──► RuleEngine.classify() ──► {path: [RuleMatch…]}
        │                                        │
        ├──► GUI：筛选面板 + chips + 原因        │
        └──► CLI：classify 报告 / filter 列表    │
                                                 ▼
                                    筛选结果视图（虚拟视图，不动原片）
```

筛选永远只是**视图**——不移动、不重命名、不删除任何文件，符合原片安全原则。

## 5. 报告与可解释性

`classify` 报告示例：

```
规则分类完成（共 3,000 张）
  夜景  Night        ： 412 张（时间窗 18:00–06:00）
  高感  High ISO     ： 286 张（ISO ≥ 3200）
  慢门  Slow shutter ：  95 张（快门 < 1/30s）
  ...
匹配原因示例 / why:
  DSC_0012.NEF  夜景：拍摄时间 20:15 在夜间时段；高感：ISO 6400 ≥ 3200
```

`filter` 列出命中文件及原因（`--explain` 展开详情）：

```
python -m src.main filter --rules night,high_iso --and
python -m src.main filter --rules night,telephoto --or --explain
```

## 6. 测试方案

- **单规则测试**：命中 / 不命中 / 边界（ISO 恰好 3200 应命中 `≥`；
  快门恰好 1/30 不应命中 `< 1/30`）、EXIF 缺失；
- **原因文本**断言（如 `ISO 6400 ≥ 3200`）；
- **配置覆盖**测试（自定义夜间时段、自定义阈值）；
- **集成**：扫描文件夹 → `classify` 计数；CLI filter 输出；
  GUI：勾选复选框 → 行数正确变化；
- **性能基线**：1 万个合成 `PhotoInfo`，全量分类在时间预算内
  （如 < 500ms），保证 GUI 流畅。

## 8. 决策记录（2026-10-18 已确认）

| 决策 | 结论 |
| --- | --- |
| **D1 夜景定义** | **先时间窗、V2.x 升级**：V2 用可配置固定时间窗（默认 18:00–06:00）；V2.x 再用 GPS+日期本地计算精确日落日出 |
| **D2 自定义规则** | **V2 不做用户自定义规则**：内置 6 条规则 + 阈值可调；自定义规则编辑器放 V2.x |
| **D3 按拍摄地点** | **GPS 列表 + 坐标**：V2 列出有 GPS 的照片并显示/复制经纬度；地图与地区命名放后续 |
| **D4 标签 chips** | **V2 就显示**：结果卡片显示规则命中标签 chips，未来与 V3 用户标签合并 |
| **D5 大光圈规则** | **加入**：`fast_lens`（f/2.8）纳入 V2 |

## 9. 对后续版本的影响

- V3（标签系统）：规则命中成为「自动标签」，用户标签在同一模型上叠加，
  无需返工；
- V4（智能筛选）：复用并扩展本方案的 AND/OR 引擎，在标签之上加数值条件；
- V2.5（质量分析）：独立扩展规则模块（模糊/曝光/重复是图像级，不是 EXIF 级）。
