# PhotoClassifier V3.5 Plan: Visual Auto-Tagging (for review)

> Status: **planning draft (2026-10-23)**. Planning only; no implementation code.
> Start with a 1–2 day feasibility test. If the gate is not met, stop.

> This is the original design. For the implemented person preview and newer benchmarks, see the [validation report](v3.5-validation.zh-CN.md).

> **Progress update (2026-11-17):** The original plan favored Places365. After a trial on 20 JPGs and 3 NEFs, CLIP ViT-B/32 int8 became the leading candidate for evaluation against human labels. The trial verified offline inference; accuracy evaluation is pending. See the [model comparison report (Chinese)](v3.5-model-compare.zh-CN.md).

> **Evaluation set ready:** The 150 photos are split by shoot into 90 calibration photos and 60 holdout photos. JPEGs were preferred for matched RAW/JPEG pairs, and near-duplicate frames were filtered. The annotation page hides model predictions. Once labeling is complete, use the calibration set to fit label thresholds and the holdout set to report precision, recall, and F1. Each label needs at least five positive and five negative examples in each split to receive a score. Labels below that minimum need more examples.

> **First evaluation result:** All 150 photos were reviewed. After excluding eight uncertain photos, 84 were used for calibration and 58 for holdout evaluation. CLIP int8 missed the overall accuracy gate. City was the only core label to reach both 80% precision and 0.75 F1. Water and flowers had too few examples.

## 0. Summary

V3.5 adds **content tags** (architecture, sky, water, sunset, city, flowers,
people, landscape) to complement V3's manual tags and EXIF-rule tags.

Recommended path:

- **Local, offline, ONNX Runtime**; no cloud by default;
- **Scene tags first**; person detection is an optional second phase;
- AI labels are **stored, displayed and filtered separately**; never merged into
  user tags automatically;
- Spend 1–2 days evaluating on 150 real photos; only build the product if the
  quality gate is met.

---

## 1. Goals and non-goals

### Goals

1. One-click content recognition after scan/quality analysis;
2. Each photo gets a few content labels with confidence;
3. Filter by AI labels; show confidence in the detail panel;
4. Fully offline; photos never uploaded;
5. One bad photo must not stop the batch;
6. Results can be cleared and re-run; model upgrades can replace old results.

### Non-goals (V3.5)

- No auto-delete, auto-pick or auto-merging into user tags;
- No Chinese semantic search;
- No model training/fine-tuning;
- No cloud API by default;
- No duplication of reliable EXIF tags (night, telephoto, slow shutter);
- No video content recognition (videos are skipped).

## 3. Label taxonomy

V3.5 starts with **8 content labels**, avoiding EXIF overlap:

| AI label | Meaning | Main source |
| --- | --- | --- |
| Architecture | building facades, bridges, interiors | scene classifier |
| City | streets, skyline | scene classifier |
| Sky | large sky area | scene classifier |
| Water | lake/river/sea/reflections | scene classifier |
| Sunset | sunset/sunrise warm sky | scene + colour cue |
| Flowers | flowers/garden | scene classifier |
| Landscape | nature, mountains, forest, grassland | scene classifier |
| People | at least one person | object detector (phase 2) |

Notes:

- **Night, telephoto, slow shutter** are already reliable EXIF tags; do not
  duplicate them with AI;
- no long-tail labels such as sport/food/animals in the first batch;
- Chinese labels are fixed; same names as user tags do not merge.

### Confidence and multi-label

- scene classifier top-k mapped to the labels above;
- several classes may map to one label; keep the highest score;
- at most **3 AI labels per photo**;
- drop labels below the threshold;
- per-label thresholds (e.g. sky 0.55, architecture 0.60, people 0.70).

## 4. Technical options

| Option | Example | Pros | Cons | Verdict |
| --- | --- | --- | --- | --- |
| A. Traditional CV | colour/edges/lines/sky segmentation | no model, fast | unusable for architecture/people/flowers | no |
| B. Scene classification | Places365 ResNet18 / MobileNetV3 (ONNX) | offline, small, fast, scene labels | weak on people/objects; mapping needs calibration | **primary** |
| C. Object detection | YOLO11n / YOLOv8n (ONNX) | people/vehicles/animals | no architecture/sunset; licence check | optional phase 2 |
| D. Zero-shot | CLIP / MobileCLIP (ONNX) | flexible labels, no training | threshold tuning, larger/slower | compare in M0 |
| E. Cloud API | general vision APIs | high accuracy, quick | privacy, cost, network, not offline | no by default |

### Recommendation

- **Primary: Places365 scene classifier** (ResNet18 or MobileNetV3, ONNX);
- compare with **CLIP zero-shot** during M0;
- add a lightweight person detector only after scene tags are stable;
- use **ONNX Runtime**; do not ship PyTorch.

### Licence caution

- verify weights and inference-code licences for every model;
- Ultralytics YOLO is AGPL; be careful if the project is distributed, or choose a
  BSD/Apache detector;
- check Places365 and CLIP weight licences during M0 before bundling/downloading.

## 5. Storage

### Dedicated table `photo_ai_labels`

```sql
CREATE TABLE photo_ai_labels (
    path           TEXT NOT NULL,
    label          TEXT NOT NULL,
    confidence     REAL NOT NULL,
    model          TEXT NOT NULL,
    model_version  TEXT NOT NULL,
    created_at     TEXT NOT NULL,
    PRIMARY KEY (path, label, model)
);
CREATE INDEX idx_ai_label ON photo_ai_labels (label, confidence);
CREATE INDEX idx_ai_path ON photo_ai_labels (path);
```

Why:

- AI output is a prediction, not a user-confirmed tag;
- no name collision with user tags;
- model/version/confidence can be recorded for re-runs;
- clearing AI labels is one `DELETE`.

### Schema migration

- current `user_version = 2`; V3.5 goes to **3**;
- additive only; `photos` / `tags` / `photo_quality` untouched;
- old databases create the table automatically; no rescan.

### Filtering extension

`FilterSelection` gains:

```python
ai_labels: frozenset[str] = frozenset()
ai_min_confidence: float = 0.5
```

- shares the global AND/OR with rules/quality/user tags;
- `matches()` receives `ai_hits: Mapping[str, float]`;
- only labels with `confidence >= ai_min_confidence` count;
- CLI: `filter --ai Architecture,Sky`, optional `--ai-min 0.6`;
- GUI: "AI tags" checkboxes in the left panel.

## 6. Inference pipeline

```text
photo path
  → preview.load_rgb_preview()       # NEF embedded JPEG / JPEG / PNG
  → resize 224/448 + normalize
  → ONNX Runtime session.run()
  → class scores → 8 Chinese labels
  → threshold + at most 3 per photo
  → write photo_ai_labels in batches
```

Key points:

- **no RAW pixel decoding**; reuse the NEF embedded preview;
- preview must provide RGB; extend `preview.py` without breaking quality analysis;
- load the model once (`InferenceSession` reuse);
- batch size 4–8; configurable CPU threads;
- reuse the quality-scan progress/cancel pattern;
- incremental: skip photos already tagged with the current `model_version`;
  `--force` re-runs everything;
- per-photo failures are recorded and skipped;
- videos are skipped.

### Model cache and download

- models are not committed to git;
- `tools/download_models.py` downloads to `models/` (gitignored) with SHA256;
- first use prompts "about XXX MB download";
- fully offline afterwards;
- dependencies in `requirements-ai.txt` (`onnxruntime`, optional
  `onnxruntime-gpu`);
- CPU default; GPU optional, verify RTX 5060 / CUDA compatibility.

## 7. CLI

```bash
# run inference on the whole library or one folder
python -m src.main autotag --model places365
python -m src.main autotag --folder "D:\Photos\2026"
python -m src.main autotag --force
python -m src.main autotag --limit 50
python -m src.main autotag --report

# inspect AI labels
python -m src.main ai-labels --db data/photos.db

# filter by AI labels
python -m src.main filter --ai Architecture,Sky
python -m src.main filter --ai Architecture --ai-min 0.7
```

Rules:

- `autotag` is incremental by default;
- `--report` prints per-label counts, mean confidence and timing;
- failed photos are summarized, not spammed;
- missing model → clear message with the download command.

The left panel is already dense. V3.5 must:

- keep "AI tags" collapsed by default and only show it after inference;
- not add another row of always-visible checkboxes;
- not add a result-table column;
- use "AI tags" consistently, never mix it with "auto tags".

## 9. Evaluation and go/no-go

### M0 validation (1–2 days, do this first)

1. Sample **150 photos** covering architecture, city, sky, water, sunset,
   flowers, landscape, people; at least 15 per class; include hard cases (night,
   backlight, indoor, blur, duplicates);
2. manually multi-label them (labels only; photos are never committed);
3. run two candidates:
   - Places365 ResNet18 / MobileNetV3 (ONNX);
   - CLIP zero-shot (ONNX, English prompts mapped to Chinese labels);
4. report:
   - per-label precision / recall / F1;
   - macro F1;
   - per-photo latency (CPU; GPU optional);
   - model size and peak memory;
   - failure cases.

### Go gate

All must hold:

- core labels (architecture/sky/water/sunset/city) **F1 ≥ 0.75** with precision
  ≥ 0.80;
- macro F1 ≥ 0.70;
- CPU ≤ **0.3 s/photo** (1,375 photos ≤ 7 minutes);
- model + runtime ≤ **500MB**;
- works fully offline; no photo uploads;
- licence permits use/distribution.

If not met: stop; consider another model, a narrower label set, or drop the idea.

### M0 deliverable

- labelled CSV / evaluation scripts under `eval/` (local; no photos committed);
- a one-page report: metrics, failure cases, recommended model and thresholds;
- your signed go/no-go.

## 12. Risks and mitigations

| Risk | Impact | Mitigation |
| --- | --- | --- |
| Accuracy too low | labels not trusted | M0 evaluation; per-label thresholds; keep high confidence only |
| Labels differ from expectations | architecture labelled city | mapping table configurable; failure-case regression |
| Model licence | cannot distribute | check in M0; prefer MIT/BSD/Apache; avoid AGPL detector |
| Dependency size | large install | models downloaded on demand; only ONNX Runtime, no PyTorch |
| CPU too slow | long waits | 224px, batching, threads; GPU optional; try 50 first |
| GPU compatibility | RTX 5060/CUDA mismatch | CPU default; GPU optional experiment |
| More UI clutter | user confusion | collapsed AI group, no result column, consistent naming |
| AI pollutes user tags | data mess | separate table; no auto-merge; clear action |
| Model upgrades | stale results | record model_version; incremental re-run |
