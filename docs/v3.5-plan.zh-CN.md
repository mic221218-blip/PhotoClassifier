# PhotoClassifier V3.5 规划：视觉自动标签（方案待确认）

> 状态：**规划稿（2026-10-23）**。本文件只做方案，不写实现代码。
> 先做 1–2 天可行性验证；验证不达标就停，不进入正式开发。

> 这是原始方案。已实现的人物试用功能和后续性能数据见 [V3.5 验收与性能记录](v3.5-validation.zh-CN.md)。

> **进度更新（2026-11-17）**：原方案优先考虑 Places365。随后在 20 张 JPG 和 3 张 NEF 上试跑，暂选 CLIP ViT-B/32 int8 进入人工标注评测。试跑只验证本地推理可行，准确率仍待验收。详见[模型对比报告](v3.5-model-compare.zh-CN.md)。

> **评测样本已准备**：150 张照片按拍摄来源划分为 90 张调参与 60 张验收样本。同组 RAW 与 JPG 优先选 JPG，并过滤近似画面。标注页隐藏模型预测；标注完成后，只用调参集确定各标签的阈值，再用验收集报告查准率、召回率和 F1。每个标签在两组中各需至少 5 个正例和 5 个负例才能参与本轮验收；覆盖不足的标签列为待补样本。

> **首轮评测结果**：150 张全部审阅，排除 8 张不确定样本后，用 84 张调参、58 张验收。CLIP int8 未达到整体准确率门槛。核心标签中只有城市达到查准率 80% 与 F1 0.75 两项门槛，水面和花卉样本不足。

## 0. 结论摘要

V3.5 的目标是让照片**自动获得内容标签**（建筑、天空、水面、日落、城市、花卉、人物、风光……），
补上 V3 只有“手动标签 + EXIF 规则标签”的缺口。

建议路线：

- **本地、离线、ONNX Runtime**，不默认走云端；
- **先只做场景标签**，人物检测作为第二阶段可选项；
- AI 标签**单独存储、单独展示、单独筛选**，不自动混进用户标签；
- 先花 1–2 天在 150 张真实照片上评测，达到门槛再写产品代码。

## 1. 目标与非目标

### 目标

1. 扫描/质量分析之后，可一键对照片做内容识别；
2. 每张照片得到若干内容标签 + 置信度；
3. 左侧可以按 AI 标签筛选，详情能看到置信度；
4. 全程离线，照片不上传；
5. 失败只影响单张，不阻塞整批；
6. 可清空、可重跑，模型升级后能识别旧结果。

### 非目标（V3.5 不做）

- 不做自动删除、自动精选、自动合并用户标签；
- 不做中文语义搜索；
- 不做模型微调/训练；
- 不做云端 API（可作为未来可选项，但默认关闭）；
- 不把 EXIF 已能可靠判断的标签（夜景、长焦、慢门）重复做成 AI 标签；
- 不做视频内容识别（视频跳过）。

## 3. 标签体系

V3.5 第一批只做 **8 个内容标签**，避免与 EXIF 规则重复：

| AI 标签 | 说明 | 主要来源 |
| --- | --- | --- |
| 建筑 | 建筑立面、桥梁、室内建筑结构 | 场景分类 |
| 城市 | 城市街景、天际线 | 场景分类 |
| 天空 | 大面积天空 | 场景分类 |
| 水面 | 湖、河、海、倒影 | 场景分类 |
| 日落 | 日落/日出暖色天空 | 场景分类 + 颜色辅助 |
| 花卉 | 花、花园 | 场景分类 |
| 风光 | 自然景观、山、森林、草原 | 场景分类 |
| 人物 | 画面中有人 | 目标检测（第二阶段） |

说明：

- **夜景、长焦、慢门**已经由 EXIF 规则稳定判断，不再做 AI 标签，避免重复；
- 第一批不做“运动”“美食”“动物”等长尾标签；
- 标签名固定为中文，与预置标签同名时也不合并。

### 置信度与多标签

- 场景分类输出 top-k，映射到上述标签；
- 同一标签可由多个类别合并，取最高分；
- 每张照片最多保留 **3 个** AI 标签；
- 低于阈值的直接丢弃，不展示“猜”的标签；
- 阈值按标签分别校准（例如天空 0.55、建筑 0.60、人物 0.70），不搞一个全局值。

## 4. 技术路线对比

| 路线 | 代表 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A. 传统 CV | 颜色/边缘/直线/天空分割 | 零模型、快 | 建筑/人物/花卉基本不可用，阈值脆弱 | 不采用 |
| B. 场景分类 | Places365 ResNet18 / MobileNetV3（ONNX） | 离线、模型小、CPU 快、场景标签直接 | 人物/物体弱，类别映射需校准 | **首选** |
| C. 目标检测 | YOLO11n / YOLOv8n（ONNX） | 人物/车/动物准 | 不能判断建筑/日落；许可证需确认 | 第二阶段可选 |
| D. 零样本分类 | CLIP / MobileCLIP（ONNX） | 标签自由、无需训练 | 阈值难调、CPU 较慢、模型较大 | 备选，与 B 对比 |
| E. 云端 API | 通用视觉 API | 精度高、接入快 | 隐私、费用、网络、不可离线 | 默认不做 |

### 推荐

- **首选 B：Places365 场景分类**（ResNet18 或 MobileNetV3，ONNX）；
- M0 阶段同时测一个 **CLIP 零样本** 作为对照，看谁在你的照片上更准；
- 人物标签等场景标签稳定后，再用轻量检测器补；
- 所有模型走 **ONNX Runtime**，不引入 PyTorch 运行时。

### 许可证注意

- 模型权重和推理代码的许可证必须逐个确认；
- YOLO 系列（Ultralytics）是 AGPL，若本项目要分发，需要谨慎或换用 BSD/Apache 的检测模型；
- Places365 权重、CLIP 权重的许可证在 M0 阶段核对，确认后再下载/打包。

## 5. 存储设计

### 方案：独立表 `photo_ai_labels`

```sql
CREATE TABLE photo_ai_labels (
    path           TEXT NOT NULL,
    label          TEXT NOT NULL,
    confidence     REAL NOT NULL,
    model          TEXT NOT NULL,
    model_version  TEXT NOT NULL,
    created_at     TEXT NOT NULL,
    PRIMARY KEY (path, label, model)
);
CREATE INDEX idx_ai_label ON photo_ai_labels (label, confidence);
CREATE INDEX idx_ai_path ON photo_ai_labels (path);
```

理由：

- AI 结果是“预测”，不是用户确认的标签，不应污染 `tags`；
- 同名标签（用户也建了“建筑”）不会冲突；
- 可以记录模型名/版本/置信度，方便重跑和回滚；
- 清空 AI 标签只需 `DELETE FROM photo_ai_labels`。

### Schema 迁移

- 当前 `user_version = 2`，V3.5 升到 **3**；
- 纯加法迁移，不动 `photos` / `tags` / `photo_quality`；
- 旧库打开自动建表，无需重扫。

### 筛选扩展

`FilterSelection` 增加：

```python
ai_labels: frozenset[str] = frozenset()
ai_min_confidence: float = 0.5
```

- 与规则/质量/用户标签共用同一个 AND/OR；
- `matches()` 接收 `ai_hits: Mapping[str, float]`（标签→置信度）；
- 只统计 `confidence >= ai_min_confidence` 的标签；
- CLI：`filter --ai 建筑,天空`，可选 `--ai-min 0.6`；
- GUI：左侧“AI 标签”勾选，使用同一 并且/或者。

## 6. 推理管线

```text
照片路径
  → preview.load_rgb_preview()       # NEF 内嵌 JPEG / JPEG / PNG，RGB
  → resize 224/448 + normalize
  → ONNX Runtime session.run()
  → 类别分数 → 映射到 8 个中文标签
  → 阈值过滤 + 每张最多 3 个
  → 写 photo_ai_labels（同一事务按批）
```

关键点：

- **不读 RAW 像素**，继续复用 NEF 内嵌预览；
- 预览需要 RGB；现有 `preview.py` 主要产出灰度，V3.5 增加 RGB 入口，不破坏质量分析；
- 模型只加载一次（`InferenceSession` 复用）；
- 批大小 4–8，CPU 线程数可配置；
- 进度、取消、错误处理复用 `quality_scan` 的模式；
- 增量：只处理“没有当前 `model_version` 结果”的照片；`--force` 重跑；
- 单张失败写不进结果，但记录错误，不中断整批；
- 视频跳过。

### 模型缓存与下载

- 模型不提交到 git；
- 新增 `tools/download_models.py`，按 SHA256 下载到 `models/`（gitignore）；
- 首次使用提示“需要下载约 XXX MB 模型”；
- 下载后可完全离线；
- 运行依赖放 `requirements-ai.txt`（`onnxruntime`，可选 `onnxruntime-gpu`）；
- CPU 版默认；GPU 版为可选加速，需验证 RTX 5060 / CUDA 兼容性。

## 7. CLI

新增：

```bash
# 对全库或某个文件夹做 AI 识别
python -m src.main autotag --model places365
python -m src.main autotag --folder "D:\Photos\2026"
python -m src.main autotag --force          # 忽略缓存，全部重跑
python -m src.main autotag --limit 50       # 先试 50 张
python -m src.main autotag --report         # 只输出评测/统计，不写库

# 查看 AI 标签
python -m src.main ai-labels --db data/photos.db

# 按 AI 标签筛选
python -m src.main filter --ai 建筑,天空
python -m src.main filter --ai 建筑 --ai-min 0.7
```

约定：

- `autotag` 默认增量；
- `--report` 输出每个标签的数量、平均置信度、耗时；
- 失败照片在报告中列数量，不逐张刷屏；
- 模型未下载时给出明确提示和下载命令。

## 9. 评测与 Go / No-Go

### M0 验证（1–2 天，先做这个）

1. 从真实库抽取 **150 张**照片，覆盖：
   - 建筑、城市、天空、水面、日落、花卉、风光、人物；
   - 每类至少 15 张；
   - 包含难例：夜景、逆光、室内、模糊、重复；
2. 人工多标签标注（只记标签，不提交照片本身）；
3. 跑 2 个候选：
   - Places365 ResNet18 / MobileNetV3（ONNX）；
   - CLIP 零样本（ONNX，英文 prompt 映射中文标签）；
4. 输出：
   - 每个标签的 precision / recall / F1；
   - macro F1；
   - 单张耗时（CPU，GPU 可选）；
   - 模型体积、内存峰值；
   - 失败案例。

### Go 门槛

必须同时满足：

- 核心标签（建筑/天空/水面/日落/城市）**F1 ≥ 0.75**，且 precision ≥ 0.80；
- macro F1 ≥ 0.70；
- CPU 单张 ≤ **0.3 秒**（1,375 张 ≤ 7 分钟）；
- 模型 + 运行时 ≤ **500MB**；
- 完全离线可运行，照片不出本机；
- 许可证允许本项目使用/分发。

不达标：停止，不进入正式开发；可以考虑换模型、缩小标签范围，或明确放弃。

### M0 交付物

- `eval/` 下的标注 CSV / 评测脚本（本地，不提交照片）；
- 一页评测报告：指标、失败案例、推荐模型与阈值；
- 你签字确认的 Go / No-Go。

## 12. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 准确率不够 | 标签不可信，用户不用 | M0 先评测；阈值按标签校准；只保留高置信 |
| 场景标签与用户预期不一致 | “建筑”识别成“城市” | 标签映射表可配置；失败案例回归 |
| 模型/权重许可证 | 不能分发 | M0 核对；优先 MIT/BSD/Apache；AGPL 检测器慎用 |
| 依赖体积 | 安装包变大 | 模型按需下载；运行时只加 ONNX，不加 PyTorch |
| CPU 太慢 | 1,375 张要等太久 | 224px、批处理、多线程；GPU 可选；先跑 50 张试 |
| GPU 兼容 | RTX 5060 驱动/CUDA 不匹配 | 默认 CPU；GPU 作为可选实验，不影响主流程 |
| 界面更复杂 | 用户更晕 | AI 标签默认折叠、不加结果列、独立命名 |
| 错误结果污染用户标签 | 数据混乱 | 独立表；不自动合并；可一键清空 |
| 模型升级 | 旧结果过期 | 记录 model_version；增量重跑 |
